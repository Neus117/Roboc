# Roboc 视觉规范

本文件是界面重绘与新增窗口的唯一依据。**所有数值在此声明一次，代码中不得再出现第二处。**

来源：进度窗（`ProgressWindow.cs`）经五轮实测定稿的参数，2026-10-12 经用户确认。

**2026-10-15 增补十四至十七节**：命名规则、交互规范、自绘判据、自检清单。
前十三节管**绘制**，后四节管**文字与交互** —— 两者改动判据不同：绘制以像素为准，
文字以十四节为准。

---

## 一、根本原则

### 1. 一切尺寸以磅（pt）和逻辑像素声明

**物理像素不是尺寸单位，是显示器的单位。**

这台开发机是 2560×1600 @ **175% 缩放**（DPI 168）。同一个 `-12` 像素的字高：

| | 物理像素 | 相对系统 UI |
|---|---|---|
| 系统 UI 9pt | 21 px | 基准 |
| 固定 `-12` px | 12 px | **57%** ← 曾因此被判定"字太小" |

**规则**：

```csharp
// 字体：磅 → 像素，由 DPI 换算
int height = -(int)Math.Round(points * dpi / 72.0);

// 布局：按 96 DPI 声明逻辑像素，用时换算
private static int Scaled(int pixels, int dpi) => pixels * dpi / 96;
```

### 2. 窗口创建前必须用 `GetDpiForSystem()`

`GetDpiForWindow(0)` 在窗口存在前**恒返回 96**，与显示器无关。曾因此让窗口按 96 DPI 定尺寸、字体按 168 DPI 定大小，**文字比窗口宽 75%**。

窗口矩形还要算上边框与标题栏：

```csharp
AdjustWindowRectExForDpi(ref rect, style, 0, 0, dpi);
```

### 3. 字号基准：正文 = 系统 UI 的 9pt

| 元素 | 磅值 | 175% 下的像素 |
|---|---|---|
| 标题行 | 10 pt | 23 px |
| **百分比** | **19 pt** | **44 px** |
| **正文** | **9 pt** | **21 px**（= 系统 UI） |

**正文必须等于系统 UI 的 9pt**，不是"看起来差不多"。

## 二、纵向节奏

单位：96 DPI 逻辑像素。**每一条带只声明一次。**

```
 20  标题行 (10pt, ~13px)        20 .. 33
 46  百分比 (19pt, ~25px)        46 .. 71
 86  当前文件名 (9pt, ~12px)     86 .. 98
108  进度条 (8px)               108 .. 116
134  速率曲线 (92px 固定)        134 .. 226
250  详情三行 (行距 26px)        250 .. 306
────────────────────────────────────────────
客户区高度 320，末行距底边 14
窗口 510 x 352 逻辑
```

**两条铁律**：

1. **曲线高度固定（92），不用"剩余空间"。** 弹性高度会吸收所有文本带之间的舍入差，导致它这次贴住详情、下次悬空。
2. **改动任何一条带，必须重算整条节奏。** 曾把卡片缩小 15%、字号减 1pt 而未重排，结果文件名长进进度条、详情块飘离底边。

## 四、配色

**从系统读取，不写死。** 写死一套会在另一种主题下变成低对比度灰字。

| 用途 | 来源 |
|---|---|
| 深浅主题 | `HKCU\...\Themes\Personalize\AppsUseLightTheme` |
| 强调色 | `HKCU\Software\Microsoft\Windows\DWM\AccentColor`（**ABGR**，需 `& 0x00FFFFFF`） |
| 曲线填充 | 强调色向白推 0.72 |
| 曲线描边 | 强调色本身 |
| 轨道/网格 | 浅色 `#E1E1E1` / 深色 `#383838` |
| 次要文字 | 浅色 `#5D5D5D` / 深色 `#B0B0B0` |

## 五、窗口外观

```csharp
// 固定尺寸对话框，不是文档窗口
private const uint WindowStyle = WS_OVERLAPPED | WS_CAPTION | WS_SYSMENU;

// Win11 圆角
int round = 2;   // DWMWCP_ROUND
DwmSetWindowAttribute(hwnd, 33, ref round, sizeof(int));
```

**不要启用 Mica**（`DWMWA_SYSTEMBACKDROP_TYPE`）。它的前提是窗口不自己绘制背景；自绘窗口启用它只会让 DWM 合成的阴影与材质混成窗外一圈不规则半透明污渍。

**不要用 `WS_THICKFRAME`。** 原生进度对话框本身是固定尺寸的；可调边框会让合成边缘与自绘内容对不齐。

## 六、绘制

### 必须双缓冲

```csharp
nint screen = GetDC(hwnd);
nint buffer = CreateCompatibleDC(screen);
nint bitmap = CreateCompatibleBitmap(screen, width, height);
nint previous = SelectObject(buffer, bitmap);
// ... 全部绘制到 buffer ...
BitBlt(screen, 0, 0, width, height, buffer, 0, 0, 0x00CC0020);
```

每秒十次重绘时，直画窗口会在每次重绘的瞬间露出被擦除一半的状态。

### `WM_PAINT` 必须 `BeginPaint` / `EndPaint`

```csharp
case WM_PAINT:
    BeginPaint(hwnd, out PAINTSTRUCT paint);
    Paint(hwnd);
    EndPaint(hwnd, ref paint);
    return 0;
```

**不验证更新区域，Windows 会立刻重发 `WM_PAINT`，无限循环**，而 `WM_TIMER` 是低优先级消息，会被这个循环挤掉。

### 每个 GDI 对象都要 `DeleteObject`

画刷、画笔、区域，一个都不能漏。**每个进程的 GDI 对象配额是有限的**，每次刷新泄漏三个，几分钟后所有绘制调用静默失败——**画面变空白而不是变错，极难定位**。

## 七、速率曲线

**两级平滑，各解决一个问题：**

| 级别 | 方法 | 解决的问题 |
|---|---|---|
| 一 | 移动平均，**窗口 3** | 瞬时速率是尖刺状的（取决于那 0.1 秒完成了哪些文件），直画是一把梳子 |
| 二 | Catmull-Rom 样条 → 三次贝塞尔 | 平滑后仍有折角；用前后邻居求切线使连接处连续 |

**采样**：120 个 × 100ms = 12 秒历史。采样数决定横向分辨率——60 个铺满 892 像素时每 15 像素一个折点。

**填充与描边必须共用同一条路径**：

```csharp
BeginPath(dc);
MoveToEx(dc, points[0].X, points[0].Y, 0);
PolyBezierTo(dc, curves, curves.Length);
LineTo(dc, x + width, y + height);   // 沿基线闭合
LineTo(dc, x, y + height);
EndPath(dc);
StrokeAndFillPath(dc);               // 画刷填充 + 画笔描边
```

分别构建多边形和折线会让两者的曲线位置不一致，边缘出现缝隙或重叠。

**数据平坦时曲线就是平的**——稳态速率画出来是一条直线，那是事实而非渲染缺陷。

## 九、网格线调参记录

**每次调整都在此记录数值，便于回溯与继续微调。**

网格线的作用是让填充区可读出幅度与时间位置。它的对比度是**在填充色与背景色之间的一个位置**，用"强调色向白推进的比例"表示——**数值越大越浅、对比越低**。

| 版本 | 横向 | 纵向 | `GraphGrid` | 说明 |
|---|---|---|---|---|
| v1 | 3 条 | — | `Lighten(rgb, 0.42)` | 首次实现，但被填充层覆盖，不可见 |
| v2 | 3 条 | — | `Lighten(rgb, 0.42)` | 修正绘制顺序后可见；用户反馈对比偏强 |
| **v3** | **3 条** | **9 条** | **`Lighten(rgb, 0.52)`** | **当前**：纵向按用户要求把矩形分成 10 栏；对比度调浅一档（+0.10） |

**参照值**：曲线填充 `Lighten(rgb, 0.72)`，背景轨道 `#E1E1E1`。网格取值介于两者之间。

**若需继续微调**，步长建议 0.05——0.10 已是可察觉的一档。

**纵向数量**：9 条把宽度分成 10 栏。这台机器上曲线区宽 892px，即每栏约 89px。

## 十、深色主题的标题栏

**窗口标题栏（非客户区）由 DWM 绘制，自绘客户区完全碰不到它。** 深色主题下若不额外声明，标题栏会一直是浅色——一条白带压在深色卡片上。

```csharp
_ = ProgressTheme.Current();          // 主题只在首次调用时确定
int dark = ProgressTheme.IsDark ? 1 : 0;

// 20 是 Windows 11；19 是 Windows 10 build 18985 之前的编号。
// 先试新的，失败再试旧的，而不是假定机器版本。
if (DwmSetWindowAttribute(hwnd, 20, ref dark, sizeof(int)) != 0)
{
    DwmSetWindowAttribute(hwnd, 19, ref dark, sizeof(int));
}
```

**必须在窗口显示之前设置**，否则会先闪一下浅色标题栏。

**这也提醒了一件事**：客户区、非客户区、以及 DWM 合成的圆角与阴影，是**三套彼此独立的机制**，各需各自的接口——改了客户区不等于改了整扇窗。

## 十一、两个"代码正确但画面空白"的陷阱

这两条都属于同一族：**代码读起来完全正确，运行也不报错，只是画面上什么都没有。** 只有截图能发现。

### 1. `DrawTextW` 的测量标志不能用于绘制

```csharp
// 测量时（正确）
DrawTextW(dc, text, len, ref rect, DT_WORDBREAK | DT_CALCRECT);

// 绘制时（曾错写成这样）
DrawTextW(dc, text, len, ref rect, DT_WORDBREAK | DT_CALCRECT);   // ← 只测量，不绘制
```

`DT_CALCRECT`（0x400）的语义就是"算出高度，然后什么都不画"。**从测量调用复制标志位到绘制调用**，结果是对话框有按钮、有边框、**没有正文**。

| 常量 | 值 | 用途 |
|---|---|---|
| `DT_WORDBREAK` | 0x00000010 | 自动换行 |
| `DT_CALCRECT` | 0x00000400 | **只测量，不绘制** |
| `DT_NOPREFIX` | 0x00000800 | 不把 `&` 当加速键 |

**绘制一律用 `DT_WORDBREAK | DT_NOPREFIX`。**

### 2. 自绘父窗口必须加 `WS_CLIPCHILDREN`

```csharp
private const uint WS_CLIPCHILDREN = 0x02000000;
private const uint WindowStyle = WS_OVERLAPPED | WS_CAPTION | WS_SYSMENU | WS_CLIPCHILDREN;
```

**没有它，父窗口的绘制不会避开子窗口。**

进度窗每秒重绘十次整个客户区，于是那两个按钮**被创建、被正确定位、然后每一帧都被涂掉**。按钮句柄始终有效——所以从代码一侧怎么看都是对的。

**规则**：任何"自绘客户区 + 真实子控件"的窗口，样式里必须有 `WS_CLIPCHILDREN`。

### 3. 顺序：DPI 必须先于布局

```csharp
ApplyWindows11Style(_window);
_dpi = ScaleFor(_window);     // ← 先确定 DPI
CreateFonts(_dpi);
Layout();                     // ← 再布局
```

`Layout` 用 `Scaled()` 定位子控件，而在 `_dpi` 仍是默认值 96 时运行它，会把控件按另一种显示器摆放。

## 十二、字号层级（最终确定）

| 用途 | 磅值 | 175% 下 | 说明 |
|---|---|---|---|
| 进度窗标题行 | **10 pt** | 23 px | **基准**——"正在将 N 个项目从 X 复制到 Y" |
| 弹窗正文 | **10 pt** | 23 px | 与基准一致 |
| 弹窗按钮 | **10 pt** | 23 px | 与正文一致 |
| 进度窗按钮 | **10 pt** | 23 px | 与正文一致 |
| 进度窗百分比 | 19 pt | 44 px | 唯一的大号元素 |
| **进度窗详情行** | **9 pt** | 21 px | **唯一的例外**：剩余项目/速度/剩余时间属于次要信息，保持小一号 |

**规则**：正文与按钮一律 10 pt。**只有进度窗的三行详情可以小于正文**，因为它们是正在被大号百分比和曲线替代的辅助读数。

曾把弹窗正文设为 9 pt——比基准小一档，结果是"同样的文字、同样的风格，但看起来不像同一个程序"。

## 十三、按钮语义色

**强调色（accent）只给"程序正在推荐的那一个动作"。**

| 位置 | 强调色按钮 |
|---|---|
| 弹窗（单按钮） | 确定 |
| 弹窗（是/否/取消） | 取消（默认动作） |
| 弹窗（是/否） | 是 |
| **进度窗（未暂停）** | **无**——暂停与取消都不是推荐动作 |
| **进度窗（已暂停）** | **继续**——它是让工作重新动起来的唯一途径 |

# 十四、命名规则

> 2026-10-15 定。来源：用户指出"所有窗口标题栏规范不统一"。
>
> 这一节管的是**文字**，前十三节管的是**绘制**。两者改动的判据不同：绘制以像素为准，
> 文字以这一节为准。

## 14.1 窗口标题：只写这件事是什么，不写程序名

程序名由**标题栏图标**承担 —— 这正是 `正在复制` 的做法，其余窗口向它看齐。

| | 中文 | 英文 |
|---|---|---|
| 复制进度 | `正在复制` | `Copying` |
| 删除进度 | `正在删除` | `Deleting` |
| 设置 | `设置` | `Settings` |
| 回收站为空 | `回收站为空` | `Recycle Bin Empty` |
| 取回确认 | `取回确认` | `Confirm Restore` |
| 停止操作 | `停止操作` | `Stop` |
| 确认卸载 | `确认卸载` | `Confirm Removal` |
| 卸载完成 | `卸载完成` | `Removed` |
| 安装完成 | `安装完成` | `Installed` |
| 保存失败 | `保存失败` | `Save Failed` |
| 注册失败 | `注册失败` | `Registration Failed` |
| 不可恢复的操作 | `不可恢复的操作` | `Irreversible Action` |
| 原路径已有同名文件 | `原路径已有同名文件` | `Name Already Exists` |
| 目标已存在同名项目 | `目标已存在同名项目` | `Name Already Exists` |

### 报错框：按成因命名，不用通用词

**报错框不再都叫「出错了」。** 标题要说清是哪一类失败：

| 情况 | 中文 | 英文 |
|---|---|---|
| 要复制的东西已被删除 | `来源不存在` | `Source Missing` |
| 目标文件夹无法创建 | `目标不可用` | `Destination Unusable` |
| 复制完成但有失败 | `复制失败` | `Copy Failed` |
| 操作被守卫拒绝（复制） | `无法复制` | `Cannot Copy` |
| 目标里已完全相同 | `无需复制` | `Nothing to Copy` |
| 取回失败 | `取回失败` | `Restore Failed` |
| 清空回收站失败 | `清空回收站失败` | `Could Not Empty the Bin` |
| 彻底删除失败 | `彻底删除失败` | `Permanent Delete Failed` |
| 操作被守卫拒绝（删除） | `无法彻底删除` | `Cannot Delete Permanently` |
| 不是文件系统项目 | `这里无法操作` | `Not a File System Item` |
| 没有收到选中项 | `没有收到选中项目` | `No Items Received` |
| 剪贴板里没有文件 | `剪贴板里没有文件` | `Clipboard Is Empty` |
| 无法写剪贴板 | `无法写入剪贴板` | `Could Not Write to the Clipboard` |
| 真的说不清是哪一类 | `出错了` | `Something Went Wrong` |

**最后一行是兜底，不是首选。** 每新增一个报错框，都要问"这一条能不能有自己的名字"。

实现位置：`MaintenanceCommands.ReportProblem(fromMenu, message, caption)` 的标题是
**参数**，默认值才是兜底那句。新增调用点时把标题传进去。

### 三条禁止

1. **不要 `Roboc — xxx` 这种前缀。** 破折号 + 程序名是原来最乱的一种写法，已全部删除。
2. **中文与英文必须同步。** 曾经出现过 `Roboc 回收站` 中文无程序名、英文写成
   `Roboc — Recycle bin` —— 两侧本身就不一致。改一侧就改两侧。
3. **英文用 Title Case，不用句首大写。** `Save Failed` 而不是 `Save failed`。

## 14.2 右键菜单项：动词或极短名词，2–4 字

| 中文 | 英文 | 命令 |
|---|---|---|
| `复制` | `Copy` | `clipboard --gui-errors "%1"` |
| `粘贴` | `Paste` | `paste --to "%V" --gui-errors` |
| `删除` | `Delete` | `purge --gui-errors "%1"` |
| `回收` | `Recycle` | `recycle --gui-errors "%1"` |
| `回收站` | `Recycle bin` | `reclaim --gui-errors` |
| `设置` | `Settings` | `settings --gui-errors` |

**父项名是 `Roboc`**（写进 `MUIVerb`）。菜单里能看到程序名，是因为那里**没有标题栏图标
可承担它** —— 这就是标题栏去程序名、菜单留程序名的理由。

> ⚠️ 已知不一致（待改）：`回收站` 的英文写成了 `Recycle bin`，按 Title Case 应为
> `Recycle Bin`。它有用户可见性 —— 卸载对话框会把它打印出来。

## 14.3 按钮：最少的字，说清点了会发生什么

| 用途 | 中文 | 英文 |
|---|---|---|
| 只有一个按钮 | `确定` | `OK` |
| 二选一 | `是` / `否` | `Yes` / `No` |
| 三选一（默认焦点在取消） | `是` / `否` / `取消` | `Yes` / `No` / `Cancel` |
| 进度卡 | `暂停` / `继续` | `Pause` / `Resume` |
| 进度卡 | `取消` | `Cancel` |
| 设置页 | `卸载` / `取消` / `确定` | `Remove` / `Cancel` / `OK` |

- `暂停` 与 `继续` 是**同一颗按钮的两种状态**，不是两颗按钮。
- `取消` 与 `否` 不同：`否` 回答一个问题，`取消` 中止一个已经开始的流程。

## 14.4 信息行：标签 + 一个空格 + 值，**不加冒号**

| 好 | 不好 |
|---|---|
| `剩余项目 10,774 (42.8 MB)` | `剩余项目: 10,774 (42.8 MB)` |
| `速度 19.2 MB/秒` | `速度: 19.2 MB/秒` |

**空格是排版，冒号是文案** —— 中文界面上半角冒号紧贴标签会显得局促，用空格已经足够
分隔，再加冒号是两重分隔。

> ⚠️ 已知不一致（待改）：`ProgressWindow.cs:565` 的**控制台**摘要版本用了
> `剩余项目: …`，而同一文件的卡片版本（`:978`）没有冒号。同一件事两处格式不同。

## 14.5 单位与数字

| 规则 | 例 |
|---|---|
| 数字用千位分隔符 | `10,774` |
| 字节单位用 `B / KB / MB / GB` | `42.8 MB` |
| 速度写成"每秒" | `19.2 MB/秒` · `19.2 MB/s` |
| 计数与单位之间空格 | `0 B` · `16 项` |
| 中文量词写在数字后 | `已回收 3 项，1 项失败` |

# 十五、交互规范

## 15.1 延迟显示：2000 ms

`ProgressWindow.DelayMs = 2000`，内部每 **50 ms** 检查一次 `_stop`。

- 延迟的目的：**在窗口存在之前**就把时间花掉，而不是先显示再隐藏。
  快到不需要它的操作从不显示 —— 这是"不打扰"而非"闪一下"。
- `Dispose()` 在延迟期内调用会**阻止窗口出现**（`_stop` 在 `Show()` 之前被检查）。
  这个机制可靠，不要绕过。
- **判据**：2 GB / 1.65 秒的操作不会出现进度窗；20,001 个小文件在 2.33 秒出现。

## 15.2 二次确认必须在别的线程上问

**不能在窗口过程里同步弹模态对话框。**

```csharp
// 错误：模态循环阻塞进度卡自己的消息循环
case WM_COMMAND:
    RequestCancel(hwnd);   // 里面同步 MessageDialog.Show(...)

// 正确：另起线程问，答案 Post 回窗口线程
_cancelAsking = true;
new Thread(() => {
    int answer = MessageDialog.Show(...);
    PostMessageW(hwnd, WM_CANCEL_ANSWER, answer, 0);
}) { IsBackground = true }.Start();
```

**症状**：确认框出现后，卡片不再重绘、暂停与关闭盒全部失效，只能用确认框把它结束掉。

**判据**（不是"看起来在动"）：确认框显示期间对卡片发 `WM_NULL` 并用
`SendMessageTimeout` 限时 1.5 秒 —— 应能收到回应；再点一次 `暂停`，应真的生效。

## 15.3 拒绝要早于进度窗

**任何会导致失败的检查，都必须发生在进度窗创建之前。**

这类缺陷在本项目**出现过三次、入口各不相同**，形状完全一样：

| 版本 | 入口 |
|---|---|
| 1.0.3 | 来源 / 目标是 shell 命名空间路径（设备） |
| 1.0.5 | 目标的上层文件夹不存在 |
| 1.0.5 | 剪贴板里的来源已被移动或删除 |

**机制**：进度窗延迟 2 秒显示。操作在这 2 秒内失败时，错误对话框先弹出，而**模态对话框
自己的消息循环会把进度窗待处理的创建消息泵出来** —— 屏幕上于是同时有一个说明框和一个
**点不动的空白进度窗**。

**看到这个形状，就往"操作是否在进度窗之前就失败了"上查。**

## 15.4 一次操作只开一个窗口

Explorer 在 `MultiSelectModel=Single` 下，**即使菜单动词不带 `%1`，也按每个选中项各调用
一次程序**。

- 带路径的动词用 `PendingSelection.TryClaim(verb, path)` 的批处理收敛成一次。
- **不带路径的动词必须用 `TryClaimImmediate(verb)`**。
  `TryClaim` 在参数为空时会**直接放行、从不加锁** —— 那个提前返回本意是让"没有东西可
  收集"的动词不必等 settle 窗口，但它把互斥也一起丢掉了。
- `回收站`、`设置`、`粘贴` 三个动词都曾因此各开 N 个窗口。

# 十六、自绘 vs 原生控件

**规则：凡是自带字体、颜色或圆角，且无法改成与其余界面一致的原生控件，一律自绘。**

已自绘：对话框按钮、复选框（`BS_CHECKBOX` 自带字体与圆角，改不动）、进度条与速率曲线
（`STATIC` 只能显示文本）、进度卡整体、设置页。

**用原生控件的地方**：只要外观不需要与自绘部分对齐，就用原生的 —— 原生控件自带键盘、
输入法、高对比度主题、屏幕阅读器的支持，自绘要一样样补回来。
