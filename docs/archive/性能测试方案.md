# 性能测试方案

**状态：待评估，尚未执行。**

目标：
- **复制/粘贴** —— 持平或略优于 `robocopy`
- **删除** —— 优于 PowerShell `Remove-Item`

---

## 一、为什么这个方案必须一次跑完

**这台机器的卷会因反复的小文件读写而劣化，只有重启能恢复。**

历史记录：

| | D: (Disk 0) | E: (Disk 1) |
|---|---|---|
| 300 × 4KB 创建 | 504 文件/秒 | 1999 文件/秒 |
| 16 MB 顺序写 + fsync | **1 MB/秒** | 289 MB/秒 |

**同一时刻、同一操作、仅卷不同——差 2000 倍。** 劣化是真实且剧烈的。

### 刚才实测的当前状态

| 卷 | 4KB 小文件创建 | 16 MB 顺序写 | 可用 |
|---|---|---|---|
| C: | 2154 文件/秒 | 1298 MB/秒 | 122 GB |
| D: | 2441 文件/秒 | 1721 MB/秒 | 334 GB |
| E: | 2004 文件/秒 | 1749 MB/秒 | 137 GB |
| **健康参照** | **约 3900 文件/秒** | — | |

**三个卷都在健康值的 55%–63%。顺序写正常，劣化集中在元数据路径。**

**这是本方案所有设计决定的前提。**

---

## 二、对抗劣化的四项措施

劣化会让"后跑的选手"吃亏，从而制造假差异。四条措施同时上：

### 1. 交错执行，不批量

```
✗ 错误：roboc ×3 → robocopy ×3 → xcopy ×3      （robocopy 系统性吃亏）
✓ 正确：roboc, robocopy, xcopy, roboc, robocopy, xcopy, ...
```

### 2. 轮转顺序

每一轮把选手顺序左移一位（拉丁方），消除"总是第一个跑"的优势。

### 3. 每轮前后测卷健康度

用已有的 `Measure-VolumeProbe`（300 × 4KB 创建）在**每一轮开始和结束**各测一次。

**如果首尾差异超过 20%，整轮数据作废并报告**——宁可说"这次环境不成立"，不拿噪声当结论。

### 4. 建议先重启

**重启能把小文件性能从 ~2400 恢复到 ~3900。** 方案不强制要求，但：

- **重启后跑**：数字好看，且更接近真实使用
- **不重启跑**：**相对比较依然成立**（所有选手同条件），只是绝对值偏低

**这一点请你决定。**

---

## 三、语料设计

**一次生成，全程复用。** 反复重建语料本身就是劣化源。

| 语料 | 形状 | 规模 | 测什么 |
|---|---|---|---|
| **A** | 海量小文件 | 20,000 × 4 KB，每目录 256 个 | **旗舰场景**——工具存在的理由 |
| **B** | 少量大文件 | 2 × 1 GB | 顺序吞吐、双缓冲路径 |
| **C** | 混合 | 10,000 小 + 1 × 2 GB | 真实负载 |
| **D** | 元数据密集 | 1,000 文件，其中含硬链接与 ADS | **本轮新增的默认路径开销** |

**语料 D 特别重要**：硬链接检测是本轮唯一改变了默认行为的东西——每个多链接文件多一次 `GetFileInformationByHandleEx`。**它值多少代价，只有量了才知道。**

用已有的 `Roboc.CorpusGen` 生成 A/B/C；D 需要扩展它（新增 `--hardlinks N --ads N`）。

## 四、选手与对照

### 复制

| 选手 | 命令 | 说明 |
|---|---|---|
| **Roboc** | `copy --to <dst> --quiet <src>` | 被测对象 |
| **Robocopy 默认** | `robocopy <src> <dst> /E /NFL /NDL /NJH /NJS /NP` | 目标基准 |
| **Robocopy /MT:32** | 同上 + `/MT:32` | 常见调优配置 |
| **Robocopy /MT:1** | 同上 + `/MT:1` | 单线程对照 |
| **xcopy** | `xcopy /E /I /Q /Y <src> <dst>` | 传统工具参照 |

**没有"资源管理器"这一项**——Explorer 复制是 GUI 操作，无 CLI。它的底层 `CopyFileEx` 可以写个壳来测，但**那是另一个程序，不是 Explorer**。

**结论：以 `robocopy` 为基准**，这也正是你设定的目标。

### 删除

| 选手 | 命令 | 说明 |
|---|---|---|
| **Roboc** | `delete --direct --yes <path>` | 被测对象 |
| **PowerShell** | `Remove-Item -Recurse -Force` | 你的目标基准 |
| **cmd** | `rd /s /q` | 传统最快路径 |

**删除测试必须在复制的目标上做**，所以每轮删除后会重建——**这正是劣化最快的操作，因此删除测试放在最后，且轮数最少。**

## 五、测量协议

### 每轮流程

```
1. 卷健康探针（前）
2. 清空目标目录
3. 对该语料，按轮转顺序执行全部选手，各计时一次
4. 每个复制结果做正确性校验
5. 卷健康探针（后）
```

### 计时

- **墙钟时间**为主指标
- 排除进程启动（单独测一次启动开销并从结果中说明，但不扣除）
- **取中位数**，同时报告 min/max——**均值会被单次抖动带偏**

### 正确性校验（不能省）

**复制得快的错误副本没有意义。** 每次复制后用 `Roboc.CorpusGen verify` 或文件计数 + 抽样哈希确认：

- 文件数一致
- 总字节一致
- 抽样内容一致

**任何一次校验失败，该选手该轮数据作废。**

### 重复次数

| 语料 | 轮数 | 理由 |
|---|---|---|
| A（小文件） | 5 | 主战场，需要统计意义 |
| B（大文件） | 3 | 方差小 |
| C（混合） | 3 | — |
| D（元数据） | 3 | — |
| 删除 | 3 | **写操作最伤卷，克制** |

### 预热

**每轮第一次运行丢弃**，不计入。

## 六、需要记录的元数据

每次运行记录，用于事后判断数据可信度：

- 时间戳
- 卷健康度（前/后）
- 墙钟时间
- 文件数 / 字节数
- 推导出的 文件/秒、MB/秒
- 进程 CPU 时间（可选，看效率而不只是速度）
- 校验结果
- 退出码

---

## 七、已知干扰因素（无法排除，但要记录）

| 因素 | 影响 | 处理 |
|---|---|---|
| **杀毒软件实时扫描** | 可能大幅影响小文件写 | 记录，不关闭（关闭会偏离真实使用） |
| **文件系统缓存** | 源数据第一次读后被缓存，**利好后跑的选手** | 交错执行摊平 |
| **热降频** | i7-12800HX 长时间高负载会降频 | 控制总时长在 10 分钟内 |
| **后台进程** | DSH 自身、编辑器等 | 测试期间不跑其他任务 |
| **卷劣化** | 见第二节 | 四项措施 |

## 八、预计耗时

| 阶段 | 时间 |
|---|---|
| 生成语料（一次） | 2–3 分钟 |
| 复制测试（5 语料 × 3–5 轮） | 5–8 分钟 |
| 删除测试 | 1–2 分钟 |
| **合计** | **约 10–13 分钟** |

**一次跑完，中途不打断。**

## 十、需要你决定的四件事

### 1. 是否先重启？

- **重启**：小文件性能从 ~2400 恢复到 ~3900，数字更接近真实使用
- **不重启**：相对比较仍成立，绝对值偏低

**我建议重启**——这是唯一一次全面性能测试，值得在最佳状态下做。

### 2. 语料放在哪个卷？

- **D:** 可用空间最大（334 GB），当前健康度最好（2441 文件/秒）
- 需要在**同卷内**复制（源与目标同卷）还是**跨卷**？

**我建议 D: → D:** 同卷，因为这是最常见的使用场景，且排除跨盘变量。

### 3. 是否扩展语料生成器以支持硬链接/ADS？

- **需要**：新增约 60 行，否则语料 D 造不出来
- **不需要**：跳过语料 D，硬链接开销无从测量

**我建议加**——那是本轮唯一的默认路径变化。

### 4. 杀毒软件要不要临时关闭？

- **不关**：数据更接近真实使用
- **关**：数据更干净，可复现性好

**我建议不关**，并在结果里注明——因为你的实际使用环境就是开着杀软的。

---

## 十一、方案不成立时的处理

**如果卷健康度在测试中崩溃**（首尾探针差异 > 20%，或绝对值跌破 1000 文件/秒）：

1. **立即停止**，不继续烧卷
2. 报告已完成的部分
3. 建议重启后重测

**宁可得到"这次没测成"，也不要得到一份看起来完整、实际被环境污染的表格。**
