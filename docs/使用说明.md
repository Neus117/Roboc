# Roboc 使用说明

**本文档列出全部特性与开关。** 技术细节与维护说明在 [开发者文档.md](开发者文档.md)。

---

# 一、右键菜单

在资源管理器中选中文件或文件夹，右键 → **Roboc** 下的六项。

| 菜单项 | 作用 | 可用条件 |
|---|---|---|
| **Roboc 复制** | 把选中项放入 Roboc 剪贴板 | 始终可用 |
| **Roboc 粘贴** | 粘贴到当前目录 | **仅在执行过"复制"之后出现** |
| **Roboc 删除** | **彻底删除**，不进任何回收站 | 需选中项目 |
| **Roboc 回收** | 移入 Roboc 回收站 | 需选中项目 |
| **Roboc 回收站** | 打开回收站目录 | 始终可用 |
| **Roboc 设置** | 打开设置窗口（含卸载） | 始终可用 |

**选中项在回收站内时，"回收"会改为提示取回**——已在回收站中的项目无法再次回收，唯一有意义的动作是放回原处。

# 二、安装与卸载

## 安装：解压后双击即可

```
1. 解压到任意文件夹
2. 双击 Roboc.exe
        ↓
   自动注册右键菜单，弹出「Roboc 已就绪」
```

**不需要命令行，不需要管理员权限。**

再次双击只会告知"已经可以使用"，不会重复注册。

## 卸载：两步

```
1. 右键任意文件 → Roboc 设置 → 点「卸载」
2. 确认后，按提示删除程序文件夹
```

**设置窗口会开列明确告诉你：**

- ✅ **清除了什么**：右键菜单（18 个注册表项）、发送到菜单、程序数据、临时痕迹
- ⚠️ **没动什么**：**回收站**——里面是你要么取回、要么自行删除的文件
- 📁 **然后删掉哪个文件夹**

**卸载后目录里只剩 `Roboc.exe` 和 `assets\`——删掉文件夹就是彻底的。**

**这就是"便携绿色"的含义**：设置存在 exe 旁边，不写注册表（除了右键菜单必须的键），不留 AppData。

# 三、设置窗口

**右键 → Roboc 设置。** 每个可选功能一个开关，**并标明它的收益、代价与默认状态**。

| 开关 | 默认 | 一句话 |
|---|---|---|
| **保留硬链接** | **开** | 同一文件的多个名字在目标侧仍是链接，不占额外空间 |
| **断点续传** | **开** | 中断后重新执行即可继续 |
| **保留数据流（ADS）** | **关** | 保留"来自 Internet"标记；代价 +3.8%~7.4% 吞吐 |
| **复制后校验内容** | **关** | 逐字节比对，能发现静默写入错误；代价 +54% 耗时 |
| **原子发布** | **开** | 目标路径永不被观察到半成品 |

**选中任一开关，窗口下半部分会显示它的收益、代价与建议。** 默认值直接标在每一行上——**"它做什么"和"它原本是什么"是两个问题，只有第二个能让你撤销一次尝试。**

**设置保存在 `<程序目录>\Roboc.settings.json`**，随文件夹一起消失。

**命令行仍可临时覆盖**：`--ads` / `--no-ads`、`--verify` / `--no-verify`、`--hardlinks` / `--no-hardlinks`。**两个方向都有**——设置里开了的功能，必须能为单次运行关掉。

# 四、默认启用的能力

**这些不需要任何操作，装好就有。**

| 能力 | 说明 |
|---|---|
| **多线程复制** | 默认 4–16 线程，按 CPU 核心数自动决定 |
| **块克隆** | 同卷 NTFS/ReFS 上近乎瞬时（服务端复制，不经过用户态） |
| **硬链接保留** | 同一文件的多个名字在目标侧**仍是链接** |
| **重解析点重建** | 符号链接、junction 在目标侧重建为链接 |
| **断点续传** | 日志在程序目录 `.roboc\jobs\` |
| **原子发布** | 目标路径**永不被观察到半成品** |
| **进度窗** | 超过约 2 秒的操作显示进度、速率曲线与剩余时间，可暂停、可取消 |

# 五、开关一览

| 开关 | 默认 | 作用 | 代价 |
|---|---|---|---|
| `--ads` | **关** | 保留备用数据流 | +3.8% ~ 7.4% 吞吐 |
| `--verify` | **关** | 复制后逐字节校验 | +54% 耗时 |
| `--checkpoint-interval <MB>` | 32 | 续传检查点间隔 | 无实测收益，见下 |
| `--workers <n>` | 自动 | 线程数 | — |
| `--buffer <bytes>` | 1 MB | 单次写入缓冲 | — |
| `--overwrite <mode>` | `skip` | 同名项目的处理 | — |
| `--no-resume` | — | 关闭断点续传 | — |
| `--no-flush` | — | 不强制大文件落盘 | **管不到检查点 flush** |
| `--always-direct` | — | 一律直接写，不用临时文件 | 失去原子性 |
| `--timing` | — | 输出各阶段耗时 | — |

## `--ads`：保留备用数据流（**默认关闭**）

```powershell
roboc copy --to "D:\目标" --ads "E:\来源"
```

**备用数据流（ADS）** 是 NTFS 允许文件携带的额外具名数据。最常见的是 **`Zone.Identifier`**，即"网络来源标记"（Mark of the Web）——**浏览器下载、邮件附件、压缩包解压出来的文件几乎都带它**。Windows 靠它决定是否提示"此文件来自其他计算机"，以及是否对 Office 文档启用保护视图。

**默认不复制**，因为：

- **探测数据流要对每个文件多一次系统调用**，实测 **19 µs/文件**（对照：读一次文件时间戳约 16 µs），折算到海量小文件场景约 **3.8%–7.4%** 的吞吐损失
- **绝大多数文件根本没有数据流**，却要为每个文件付出探测
- 很多人**恰恰希望**复制到自己硬盘后去掉网络来源标记

**什么时候该开：**

| 场景 | 建议 |
|---|---|
| 备份、归档 | **开**——数据流是数据的一部分 |
| 搬移下载来的文件 | **开**——否则安全提示静默消失 |
| 日常整理、海量小文件 | **不开** |
| 目标是 FAT32 / exFAT / 网络共享 | **开了也没用**——那些文件系统无法承载数据流 |

**开启后**：逐条复制，某一条失败**不中断整个任务**、不算文件失败，但**会在结果中列出**。

**关闭时**：不探测、不复制、不报告——这是刻意的，为了不付出探测开销。

## `--verify`：复制后校验内容（**默认关闭**）

```powershell
roboc copy --to "D:\目标" --verify "E:\来源"
```

**复制完成后，把目标文件逐个读回来与源文件逐字节比对。**

### 它防的是什么

**不是"复制被中断"**——原子发布已经保证了这一点。

**是"写入静默出错"。** 以下每一层都有自己的保护，**而没有一层检查"我请求写入的字节，是否就是最终存储的字节"**：

| 保护机制 | 保护范围 | 防不住 |
|---|---|---|
| SMB 校验和 | 网络传输 | 主机内存、存储控制器 |
| USB / SATA CRC | 线缆传输 | 驱动缺陷、LBA 写错 |
| NVMe ECC | 闪存单元 | 主机内存、固件缺陷 |
| TCP 校验和 | 网络包 | 应用层缓冲区 |

**内存位翻转、驱动缺陷、控制器写错扇区——都会产生一个大小正确、时间戳正确、能打开、内容却错了的文件。**

**Windows 原生复制不做这个检查**——资源管理器使用的 `CopyFileEx` **没有任何校验选项**，`robocopy` 同样没有。

### 代价（实测）

601 个文件 / 764 MB，各跑三次取中位数：

```
不带 --verify :  0.84 s     911 MB/s
带 --verify   :  1.29 s     591 MB/s
                 增加 54%
```

**原因直接：校验要把源和目标各读一遍。**

### 什么时候该开

| 场景 | 建议 |
|---|---|
| 复制到**移动硬盘 / U 盘** | **开**——介质与线材是薄弱环节 |
| 复制到**网络位置** | **开** |
| **怀疑硬件有问题** | **开**——这是唯一能发现问题的途径 |
| 备份**不可替代的数据** | **开** |
| 同机 NVMe 之间搬移 | 视数据重要性 |
| 日常整理 | **不开** |

### 失败时的行为

- **不中断任务**——其余文件继续
- **不删除目标文件**——报告问题让你决定。**自动删除可能把唯一一份候选数据也毁掉**
- 报告指出**哪个文件**、**从第几字节开始不同**

## `--checkpoint-interval`：续传检查点间隔（**通常不需要改**）

```powershell
roboc copy --to "D:\目标" --checkpoint-interval 128 "E:\来源"
```

**单位 MB，默认 32。**

断点续传每记录一次"已写入 N 字节"，**都要先把这 N 字节刷到磁盘**——否则断电后日志会声称拥有从未持久化的数据，续传时直接跳过它们。**所以这个值限制了写入者能领先磁盘多远。**

**曾尝试把默认值提到 256，已回退**——当时的测量结果自相矛盾（32MB:1.02s / 256MB:1.18s / 1GB:4.11s，且关掉续传反而更慢），因为顺序测量被缓存淘汰主导。

**后来的受控测量（每次运行前把源读回缓存）证明这个参数不是杠杆**：

```
32MB / 128MB / 512MB / 关闭续传  →  中位数 0.93–0.99s，极差完全重叠
```

**所以不必改它，除非你在自己的环境里测出了不同结果。**

# 六、回收站

## 位置

```
<卷>:\Roboc_bin\
```

**每个卷一个独立的回收站**，与系统回收站互不干扰。

## 取回

在回收站目录里选中项目 → 右键 → **Roboc 回收**，会提示取回原位置。

**原位置由记录还原。** 如果原位置已有同名项目，取回会被拒绝——**不会覆盖**。

## 与系统回收站的区别

| | Roboc 回收站 | 系统回收站 |
|---|---|---|
| 位置 | `<卷>:\Roboc_bin\` | `$Recycle.Bin` |
| 清空方式 | 在资源管理器中直接删除 | 右键清空 |
| 同名处理 | **拒绝放入第二份** | 自动改名 |

---

# 七、不可撤销的操作

**`Roboc 删除` 与清空回收站都无法撤销**，程序会先弹确认框。**请看清统计数字再确认。**

命令行清空回收站**必须**带 `--yes`：

```powershell
roboc reclaim --empty --yes
```

不带 `--yes` 会被拒绝——**没有其他途径可以清空回收站**。

---

# 八、删除的保护

`delete` 命令有三道防线，触发任何一道都会**拒绝执行**：

| 守卫 | 拦截 |
|---|---|
| 驱动器相对路径 | 形如 `D:` 的写法（Windows 会把它解释为"D 盘的当前目录"，而非 `D:\`） |
| 卷根目录 | 整个卷 |
| 程序自身目录 | 程序所在目录及其所有祖先 |

**这三道防线来自一次真实事故**——早年 `delete D:` 删掉了整个工作区。

# 九、常见问题

**问：粘贴菜单是灰的，点不了。**
答：先对要复制的内容执行一次 **Roboc 复制**。粘贴入口只在剪贴板中有内容时才出现。

**问：回收时报"回收站中这个位置已经有一份了"。**
答：同一个原路径已在回收站中，程序拒绝放入第二份——否则取回时无法判断该还原哪一个。请先在回收站里处理掉那一份。

**问：复制后文件的"来自 Internet"标记没了。**
答：这是默认行为。需要保留请加 `--ads`，见第三节。

**问：进度窗没有出现。**
答：操作在约 2 秒内完成时不显示。进度窗是给长任务用的。

**问：可以在操作中途取消吗？**
答：可以，进度窗上有"取消"（需二次确认）。已完成的项目会保留，尚未处理的会被放弃。

**问：中断后能续传吗？**
答：能。任务日志在程序目录的 `.roboc\jobs\` 下，重新执行同样的复制会从断点继续。

**问：复制到 U 盘时，硬链接和 ADS 会怎样？**
答：**硬链接**——FAT32/exFAT 不支持，会变成独立副本（内容正确，占用更多）。**ADS**——同样不支持，**默认也不复制**。需要时用 `--ads`，目标不支持时会报告。

**问：为什么复制大文件时比 robocopy 慢很多？**
答：**因为 Roboc 在等数据真正落盘，而 robocopy 写进缓存就返回。**

实测这个卷的持续写入速度是 **967 MB/s**，Roboc 跑到 **831–1034 MB/s**（物理极限的 86–107%），而 robocopy 自报 **11,100 MB/s**——超过该卷物理能力 11 倍，那个数字描述的是缓存，不是磁盘。

**这个等待是断点续传正确性的要求**：日志不得声称拥有断电后可能丢失的字节。

**问：`--verify` 说校验通过，但我还是不放心。**
答：校验读的是**目标文件当前的内容**。如果磁盘之后发生位翻转，那是校验之后的事——**任何工具都无法预防**。

# 十、限制与已知缺口

| 项 | 状态 |
|---|---|

| 加密文件（EFS） | **未专门支持** |
| 稀疏文件 | **未专门支持** |

# 十一、设计原则

**接受一个参数却什么都不做，比拒绝它更糟。** 拒绝只花一秒钟，虚假的保证可能让你丢掉它本该保护的数据。

所以：**能做到但默认不做的**（`--ads`、`--verify`），会明确说明代价与适用场景；**做不到的**，会直接拒绝执行并说明原因，而不是接受参数后默不作声。
